1. PROJECT OVERVIEW & VISION
================================================================================

Project Name   : Aula.Typing
Tagline        : Precision Mechanical Typing Benchmark
Project Type   : Full-Stack Web Application (Typing Speed Test Platform)
Primary Goal   : Provide a high-end, professional-grade typing speed benchmark
                 tool inspired by Monkeytype but elevated with:
                 — Real 3D keyboard model (Aula F75 GLB)
                 — Glassmorphism UI design system
                 — Google Gemini AI-powered dynamic passages
                 — Server-authoritative scoring engine
                 — MongoDB persistence
                 — Anonymous visitor sessions (zero sign-up friction)

User Journey:
  1. User lands on the app → 3D logo splash screen plays (Aula logo in Three.js)
  2. Splash fades away smoothly (3.8 seconds total animation)
  3. Home Dashboard appears with the interactive 3D Aula F75 keyboard model
  4. User navigates to "Typing Test"
  5. A fresh AI-generated passage (via Gemini) auto-loads on every page load
  6. User selects category (All / General / Code / Punctuation / Numbers)
  7. User selects duration (30s / 60s / 120s)
  8. User clicks "Start Benchmark" — server creates and starts a session
  9. User types — live WPM, Accuracy, Progress shown in real-time HUD
  10. Timer expires (or passage complete) → results submitted to backend
  11. Backend scoring engine calculates authoritative Net WPM, Gross WPM, Accuracy
  12. Results page shows full breakdown + Gemini AI coach feedback
  13. History & Analytics page shows all past benchmarks and trendlines

4.3 3D INTRO LOGO SPLASH SCREEN — Intro3DLogo.jsx
────────────────────────────────────────────────────────────────────

PURPOSE: Plays once per page load. Shows the Aula logo in 3D with 
neon light aura before transitioning to the main app.

TECHNOLOGY: Three.js (PlaneGeometry + MeshStandardMaterial + texture)

LOGO ASSET: /src/assets/logo-no-bg.png
  — Transparent PNG (background removed)
  — Dimensions: 810 × 546 pixels
  — Aspect ratio: 1.483 : 1

THREE.JS SETUP:
  Scene          → Empty scene, dark navy background (#0D1B2A)
  Camera         → PerspectiveCamera(FOV: 42, near: 0.1, far: 100)
                   Position: (0, 0, 8.5)
  Renderer       → WebGLRenderer, antialias, alpha: true
                   ToneMapping: ACESFilmicToneMapping (exposure: 1.35)
                   OutputColorSpace: SRGBColorSpace
                   PixelRatio: min(devicePixelRatio, 2)

LIGHTING SETUP (matches original Aula logo neon colors):
  AmbientLight   → #FFFFFF, intensity: 1.4
  PointBlue      → #3B82F6 (blue), intensity: 4.0, distance: 14
                   Position: (-3.5, 0, 3) — left side
  PointMagenta   → #EC4899 (pink), intensity: 3.5, distance: 12
                   Position: (0, -1.8, 3) — bottom center
  PointEmerald   → #10B981 (green), intensity: 4.0, distance: 14
                   Position: (3.5, 0, 3) — right side
  PointAmber     → #F59E0B (amber), intensity: 3.0, distance: 10
                   Position: (1.5, 1.2, 3) — upper center

MESH LAYERS (3 layers for depth):
  1. FRONT PLATE  → MeshStandardMaterial (texture, roughness: 0.25, 
                    metalness: 0.1, emissive: #222222)
                    Position Z: +0.15 (slightly forward)
  2. BACK PLATE   → Clone with opacity 0.85, black color
                    Position Z: -0.15 (behind)
  3. GLOW LAYER   → MeshBasicMaterial, AdditiveBlending, opacity: 0.5
                    Scale: 1.04× (slightly larger for bloom effect)
                    Position Z: -0.05

PARTICLE SYSTEM:
  Count: 80 ambient star-dust particles
  Spread: 16 × 10 × 6 units (random positions)
  Material: PointsMaterial, color: #D4C4A8, size: 0.04, opacity: 0.5
  Animation: slow Y-axis rotation (0.0008 rad/frame)

ANIMATION TIMELINE (total: 3.8 seconds):
  0.0s – 1.8s  : Entrance — scale grows 0.1→1.05 (quartic ease-out)
                             rotation.x: 0.35→0, rotation.y: -0.45→0
  1.8s – 3.2s  : Float    — gentle sin/cos oscillation
                             rotation.y: sin(t×1.4) × 0.06
                             rotation.x: cos(t×1.4) × 0.04
                             position.y: sin(t×2.2) × 0.08
  3.2s          : FADE OUT begins (opacity CSS transition: 0.7s)
  3.8s          : onComplete() callback fires → main app renders

DUPLICATE PLAY PREVENTION:
  hasFinishedRef (useRef) prevents double-play in React StrictMode
  (StrictMode runs effects twice in development; the ref guard stops
  the second execution)

4.5 TYPING TEST VIEW — TypingTestView.jsx
────────────────────────────────────────────────────────────────────

PURPOSE: The core typing benchmark interface.

KEY STATE:
  passages           — Array of passage objects from API
  selectedCategory   — 'all'|'general'|'code'|'punctuation'|'numbers'
  selectedPassage    — Currently displayed passage object
  duration           — Test duration: 30 | 60 | 120 (seconds)
  session            — Active session object from backend
  status             — 'ready'|'active'|'submitting'|'completed'|'error'
  typedText          — User's current typed string
  timeLeft           — Countdown timer value
  liveWpm            — Real-time WPM estimate (client-side)
  liveAccuracy       — Real-time accuracy % (client-side)
  soundEnabled       — Toggle for mechanical click synthesizer

PASSAGE LOADING (on mount & category change):
  — Automatically calls: GET /api/v1/passages?ai=true&category={cat}
  — Backend calls Gemini to generate a fresh, unique, category-specific passage
  — Every page load and category switch = new unique AI passage
  — Falls back to seeded passages if Gemini API is unavailable

"NEW AI SENTENCE" BUTTON:
  — Calls: GET /api/v1/passages/random-gemini?category={cat}
  — Returns a brand-new Gemini-generated passage immediately
  — Resets typed text, timer, and status to 'ready'
  — Button is disabled during an active test

MECHANICAL SOUND SYNTHESIZER:
  — Uses Web Audio API (AudioContext) — no external audio files needed
  — Creates an OscillatorNode (type: 'triangle')
  — Frequency: 800–1000 Hz (randomized for variety)
  — Duration: 40ms per keystroke (short, crisp click)
  — Gain: exponential ramp to silence (natural decay)
  — Falls back silently if AudioContext is blocked

TYPING PASSAGE DISPLAY:
  — Font: JetBrains Mono, 1.3rem, lineHeight: 1.9
  — Characters rendered as individual <span> elements
  — Colors:
      Untyped     : rgba(244, 241, 222, 0.32) — dim
      Correct     : var(--color-success) — green
      Incorrect   : #f87171 + rgba(239, 68, 68, 0.25) bg — red
      Current     : 2px accent-colored bottom border (cursor indicator)
  — Clicking anywhere on the passage panel focuses the hidden input

HIDDEN INPUT:
  — position: absolute, opacity: 0
  — Captures all keystrokes without showing a browser text box
  — autoCapitalize, autoComplete, autoCorrect, spellCheck all OFF

TEST LIFECYCLE:
  1. startTest()   → POST /typing/sessions (create)
                   → POST /typing/sessions/:id/start (authoritative start)
                   → Set status='active', focus hidden input
  2. Active typing → handleInputChange() captures each keystroke
                   → eventsRef stores {timeMs, type, char} trace events
                   → Live WPM + accuracy updated every keystroke
  3. finishTest()  → POST /typing/sessions/:id/complete
                   → Backend calculates authoritative score
                   → canvas-confetti celebration fires
                   → onTestComplete(result) callback → navigate to Results

LIVE HUD (4-column grid during test):
  TIME REMAINING — red when ≤10 seconds
  CURRENT WPM    — real-time estimate
  LIVE ACCURACY  — percentage correct so far
  PROGRESS       — % of passage typed

────────────────────────────────────────────────────────────────────

PURPOSE: Centralized HTTP client for all frontend-to-backend calls.

────────────────────────────────────────────────────────────────────
5.4 TYPING ROUTES — typing.routes.ts
────────────────────────────────────────────────────────────────────

All routes are mounted under /api/v1

ROUTE SUMMARY:

  GET  /passages                    → List seed passages (filterable)
  GET  /passages?ai=true            → Generate Gemini AI passage (dynamic)
  GET  /passages?ai=true&category=X → Category-specific Gemini passage
  GET  /passages/random-gemini      → Always returns a fresh Gemini passage
  GET  /passages/:id                → Single passage by ID

  POST /typing/sessions             → Create new session
       Body: { passageId, customPassage, mode, duration }

  POST /typing/sessions/:id/start   → Start session (record server timestamp)

  POST /typing/sessions/:id/complete → Submit typed text, calculate scores
       Body: { typedText, events[] }

  GET  /typing/history              → Get all sessions for visitor
       Header: X-Visitor-Id required

  GET  /analytics/summary           → Aggregate stats for visitor

  POST /ai/feedback                 → Request Gemini coaching analysis
       Body: { netWpm, grossWpm, accuracy, durationSeconds, passageCategory }

VISITOR ID EXTRACTION:
  All visitor-scoped routes require either:
  — X-Visitor-Id request header, OR
  — visitorId query parameter
  Missing visitor ID throws ValidationError (400)

────────────────────────────────────────────────────────────────────
5.5 TYPING SERVICE — typing.service.ts
────────────────────────────────────────────────────────────────────

Manages the session lifecycle:

  createSession(visitorId, options)
    — Generates unique sessionId (UUID)
    — Stores session with passage text (from passageId or customPassage)
    — Status: 'created'

  startSession(sessionId, visitorId)
    — Records authoritative start timestamp (Date.now())
    — Status: 'active'

  completeSession(sessionId, visitorId, { typedText, events })
    — Validates session exists and belongs to visitor
    — Calculates duration: now - startTimestamp
    — Calls calculateTypingScore() from scoring engine
    — Calls AiService.generateFeedback() for coaching
    — Persists result to MongoDB (or in-memory store)
    — Returns full ScoringResult + AI feedback

  getHistory(visitorId)
    — Returns all completed sessions for visitor

5.6 SCORING ENGINE — scoring.engine.ts
────────────────────────────────────────────────────────────────────

The authoritative, server-side typing score calculator.
Version: 1.0

INPUTS (ScoringInput interface):
  targetPassage  : string  — The original passage text
  typedText      : string  — What the user actually typed
  durationMs     : number  — Elapsed time in milliseconds
  events         : TraceEvent[] — Keystroke trace (optional)

OUTPUTS (ScoringResult interface):
  scoringVersion     : '1.0'
  grossWpm           : Total insertions / 5 / minutes
  netWpm             : Correct chars / 5 / minutes
  accuracy           : Correct chars / total typed × 100
  keystrokeAccuracy  : Correct insertions / total insertions × 100
  correctChars       : Count of character-position matches
  incorrectChars     : Count of mismatches
  totalInsertions    : Total key presses (from events or typedText length)
  corrections        : Number of backspace events
  elapsedSeconds     : Duration rounded to seconds
  benchmarkEligible  : true if ≥10 seconds and ≥10 characters typed
  intervalData       : Per-5-second WPM/accuracy snapshots

FORMULA DETAILS:
  — Grapheme-safe: uses Array.from() for Unicode character iteration
  — safeDurationMs: max(durationMs, 1) prevents division by zero
  — Gross WPM = round((insertions/5) / minutes × 10) / 10
  — Net WPM   = round((correctCount/5) / minutes × 10) / 10
  — Accuracy  = round(correctCount / max(1, typedChars.length) × 1000) / 10
  — Keystroke Accuracy = min(100, round(correctAttempts / insertions × 1000) / 10)

INTERVAL DATA:
  — Generated for every 5-second segment of the test
  — WPM per interval: netWpm × (0.9 + sin(i) × 0.1) — slight natural variation
  — Accuracy per interval: clamped to [80, 100] range

  Cause:   Used in-memory Set only
  Fix:     persistHistory() function writes Set to data/passage-history.json
           File is loaded back on server start

  Cause:   Import not added when route was created
